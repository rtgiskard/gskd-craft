# 清楚的逻辑与必要的信息

## 触发与边界

用于文档撰写、实质更新与结构调整，包括实现期间首次新增或改写正式说明；在动笔前判断内容与落点，不先按代码变更追加细节、再留到收尾统一整理。也可用于审阅现有文档。普通注释、聊天回复和机械改字不必展开完整流程；简单更新直接应用相关标准，不固定输出提纲或等待批准。

代拟或整理用户向他人表达想法、经历、判断与诉求的沟通内容，由 [communication](../gskd-communication/SKILL.md) 负责；按用途区分，不因内容写在文件里就视为工程文档。

沿用当前授权、目标和仓库约定，不因写文档扩大实现范围。技术方案是否成立由设计评审负责；未验证的方案不能写成已实现事实。目标是减少可避免的返工，不保证一次写对，也不替代真实使用验证。

## 动笔前的三个决定

1. **读者与用途。** 默认读者对相关领域有符合逻辑的基础认识，能理解因果、关系和示例，但不预设熟悉本项目或具体工具。确定本文是帮助操作、理解关系、判断取舍，还是提供适配参考，据此补足项目特有的概念、前提和关键差异。按疑点查实现、接口、配置及已有验证，区分事实、计划与待验证判断；只有无法自行消除且影响内容取舍的实质歧义才询问。
2. **位置与深度。** 优先更新现有权威章节，其他位置链接过去，不建立重复说明。按下表区分用途；文档名称不决定内容深度，同一 README 可以包含不同用途的章节。参考材料不必升级为完整教程，操作笔记也不自动成为现行规范。
3. **是否需要修改。** 有意义的行为、契约或设计变化更新对应文档；纯重构、内部优化和视觉润色不自动要求更新，也不能借此忽略实际契约变化。明确要求的文档任务仍须完成，仓库要求的变更记录按约定处理。

| 用途 | 应保留 | 不应混入 |
| --- | --- | --- |
| 入口文档 | 项目用途、整体关系、主要能力、必要接入信息及专题链接 | 完整操作手册、实现逐行讲解 |
| 使用说明与参考 | 典型流程、关键配置、结果和必要边界；帮助推演与适配的机制 | 与读者无关的工具教学、所有平台和例外的展开 |
| 技术设计 | 协议、所有权、不变量、资源边界、理由与替代方案；影响重要决策的代码细节 | 按源码逐项导览、无助于判断的实现流水账 |
| 迁移说明与变更记录 | 受影响用户、旧用法到新用法的必要操作、兼容边界及重要变化 | 与升级无关的编辑流水账 |
| 操作笔记与参考脚本 | 场景、必要上下文、命令与局部理由；有价值的历史操作及其适用版本或状态 | 把现场记录冒充通用步骤、把停用操作混作当前推荐入口 |

实现中的待验证假设、临时方案和排查过程留在已有任务记录或会话；影响后续实现的重要决定及理由按需进入已有设计说明，标明提案、已接受或已验证等实际状态。正式文档按稳定的机制或契约更新，不要求每个代码步骤都写一次，也不强制等全部实现结束；文档先行定义契约时，不把提案写成已实现事实。尚未稳定时只在已有记录保留受影响章节与待兑现变化，不另建文档台账；交付前仍须同步最终行为。

## 撰写与组织

让结构本身表达整体逻辑：按流程、对象关系或依赖组织，使主干意图先于枝节显现，不照搬源码目录或本次修改顺序。增量更新先读受影响章节，按变化后的概念与机制改写失效说明，不为每个新增分支在末尾追加例外；函数名、调用顺序和局部修补细节，仅在帮助读者理解关键机制、操作或取舍时保留，不以删短为目标。理解型文档先说明关键关系，操作型文档直接给典型路径，不套固定模板。正文、表格与示例按信息作用分工，不互相转述。成稿时检查解释和总结是否增加了事实、关系或判断依据；没有新增作用的合并或删除。重复若能减少跨章节查找或帮助理解，可以保留。

给足以推演的代表性路径、关键变量及调整依据，按实际需求展开平台和例外，通用工具用法链接权威资料。理由与限制紧贴具体选择：帮助理解关系、改变操作或判断保证的机制应讲清，领域常识、无关内部细节及假想误用提醒不必展开。深度取决于读者用途，不取决于篇幅；明确要求的教程或详细步骤仍须完成。

入口和用户参考直接描述现行行为，让不知道旧版本的读者也能理解。例如写“默认包含统计”，不追加“不再需要旧参数”。已移除行为只在必要的迁移说明、变更记录或明确要求时介绍；不能以清理历史背景为由删除必要升级指引。

复用项目术语与文档格式，让标题、顺序和链接帮助定位信息。可以有明确判断与自然口吻，但判断须有对象和依据，不靠空泛赞美、刻意玩笑或一律公文化来塑造风格；不以短句多或形式统一代替清楚。

## 核实与交付

- 区分可直接执行的示例、需调整的参考和历史操作，交代必要上下文、占位符及适用状态；不能把参考脚本包装成可整段运行的安装器。命令注释须符合目标输入环境，按真实入口及参数解析方式验证，不把 shell 接受等同于应用输入框接受。
- 核对说明与当前实现、接口和配置是否一致。收尾核对最终行为及在途记录中的文档变化，修正事实差异、遗漏和具体结构问题，不默认再做一轮全文重组；首次写入也应符合本文标准。复用已有有效证据，只对改变或存疑的操作语义补验代表路径，不因写文档重跑部署或展开无关调查。有副作用的操作使用隔离数据或安全环境，不直接操作用户现用实例；环境不可达则明确未验证项。
- 检查相对链接、引用目标及必要关联说明。验证保护任务结果与契约，不新增只锁定措辞、排版或源文本的永久测试。
- 交付说明改了哪些读者可见内容、实际验证及限制，不把模型解释练习当成技能发现、执行合规或用户任务成功的证明。内容满足请求且关键证据齐全即停止，不为收尾反复润色。

交付复查只核对必要文档是否同步并符合本标准，不另立写作规则；技术取舍存在疑点时，按 [设计评审](../gskd-design-review/SKILL.md#触发与边界) 检查受影响部分，不因此重新设计整项工作。
