# 设计取舍与完整接入

## 触发与边界

默认先检查当前实现、既有约定与本次目标；原因已明确且边界未变的普通修复、机械迁移，不自动展开方案比较或完整设计评审。不为使用本 Skill 凑候选方案或制造设计疑点。

干净实现是基础要求，不是用户额外提出才追求的优化：责任清楚、状态语义一致、控制流可解释，局部修复也应落在正确的责任边界。不能以改动少为由接受靠堆叠特判掩盖模型缺陷的方案；也不为形式统一引入无必要的抽象。满足这一基线不等于每次都展开设计评审或重构，改动范围仍服从任务授权。

用户要求方案比较、存在影响行为、维护成本或表达品质的实质取舍，或具体责任／生命周期／接入疑点时展开。字段承担可独立变化的语义、多个消费者重复推断同一事实、下游依赖上游编码细节，都是应按[链路分析与方案收敛](#链路分析与方案收敛)追查的信号，不必等第二次失败或用户给出替代思路。新证据推翻原先假设，或反例持续落在同一边界时，按[重复失败时](#重复失败时)重新检查共同不变量；已读过本 Skill、处于修复或收尾阶段都不免除这次判断。进入或重新进入时，简短点明本次取舍、被推翻的假设或待查边界，只追受影响的责任链和必要证据，不固定播报技能状态；受影响调用方迁移、失败处理和释放正确性仍须检查。

按当前任务区分分析与实施：方案分析、比较或问题调查，可以在调查范围内按需追查实际实现，输出事实、判断与建议；只有获得实施授权，才据此修改。调查深度不等于修改权限，实施授权也不自动要求完整设计评审。只展开当前问题所需的检查，证据充分且无新疑点即停止。本 Skill 补充常驻规则，不替代或放宽它们；不依赖任务状态工具、扩展或自动派发。

## 链路分析与方案收敛

用户明确要求相关链路分析、整体思路梳理，或出现上述责任与语义疑点时使用。找到足以解释现象的直接原因，不等于已经找到合适的修复点；也不能跳过故障机制直接归因于架构。“完整”指指定行为的责任链闭合，不是穷尽全仓和全部时序；不提供后台跟踪，也不扩大修改授权。

1. **绑定结果与范围**：复用当前目标、授权和验收，明确哪个用户结果必须成立、哪些行为保持不变。利用正常／异常路径差异定位改变结果的决定，区分触发条件、失效机制与待验证假设，不只缩小文件范围。
2. **还原因果与责任链**：读实际实现，从真实入口追到事实来源、状态转换、副作用、失败／取消、恢复与释放，以及最终消费者。明确谁创建、谁修改、谁收尾；区分提前计算、实际接纳与提交，检查部分成功及退出后的迟到结果。不同环节可确认不同事实，不默认集中到一个 owner。
3. **检验判断依据与时点**：问消费者需要什么事实，现有字段是事实本身还是代理指标，相关语义能否独立变化。真实语义不变、只改变合法表示时，决定是否应不变？表示看似不变、真实语义变化时，决定是否应改变？检查权限判定是否早于受保护的副作用；最终仍会拒绝，不证明此前没有越权操作。反事实先作为假设，用有区分力的检查取证。
4. **整合相关发现与方案**：按共同不变量归组，区分输入解释错误与消费者承担不可靠推导，两者可能同时存在。共享根因的问题一起修正；仅表面相似、责任或生命周期不同的部分保持独立，不强造通用状态机。比较修改前后承担的责任，不把重复调用等同重复工作。现有模型能表达合法状态且局部修正足够，就保留局部修复；有模型缺口才调整边界。
5. **收敛修正与证据**：说明推荐落点、保留与移除的机制、取舍及可区分方案的反例。验证既消除误触发，也保留真实边界的检测能力，不靠扩大容差、忽略事件或保留旧结果掩盖问题。发现应说明触发前提、用户影响、证据强度，区分普通业务、合法异步交错与特殊环境加固，不仅给优先级。必要改造超出授权则提出建议，不自行实施。

进入本节分析且已获实施授权时，沿用已有风险契约；首次生产修改前仅补充本次确认的机制、修正边界与区分性验证，不重复记录，也不增加审批。简单结论几句话即可，不强制输出全部步骤。后续复查针对尚未证明的假设说明新增检查，复用有效证据；约定链路与重要疑点已有结论且无新疑点即停止，不按固定轮数购买信心。


## 抽象的判断

目标是降低整体理解与维护成本，不是减少抽象。不要用类型、文件、层数、代码行数或调用者数量代替设计判断；“干净”“克制”“KISS”不默认指向内联或删减。

- **保留或新增**：抽象自然对应责任、所有权、生命周期、状态约束或真实变化边界，并把相关规则收拢在正确位置。即使只有一个调用者、尚无重复，也可以成立；不必等重复出现后才建立必要边界。
- **简化**：责任边界合理，但接口、配置能力或类型层次超过当前需要。收窄多余能力，保留边界，不把简化直接等同于拆除。
- **删除或内联**：没有独立语义、约束或生命周期责任，仅机械转发或重复表达；删除后也不会把规则、资源管理或状态转换分散给调用方。不能仅因实现短或使用少就判定多余。

工程判断关注命名是否贴合语义、接口是否完整、非法状态是否受约束、控制流与成本是否可见。自然抽象和直接实现都可以是好设计；不要预造无依据的通用框架，也不要为追求少一层而破坏已有的自然结构。

## 表达与美学品味

正确、清楚和成本合理是底线，不自动等于有美感。方案设计与 review 涉及命名、结构表达或界面取舍时，主动判断表达是否贴切、有层次，局部与整体是否协调，不等用户另行要求“有品味”；判断深度随本次取舍，不为普通修复新增审美流程。

- **代码与设计**：关注概念命名、结构与阅读节奏：业务代码像业务，I/O 代码像 I/O，音频代码像音频；连接它们的机制少、明确，而且能解释完整生命周期。执行设施留在恰当边界，不为形式统一抹平不同约束，也不把复杂度转嫁给调用方。轻量不以行数、组件、线程或依赖数量衡量；局部精巧不应引入多余概念或破坏整体风格。
- **界面与交互**：按产品气质判断比例、层级、疏密节奏、色彩材质和动态反馈，在实际上下文看组件间的关系。一致性只是秩序，不是美感的充分条件；克制不等于寡淡，紧凑不等于拥挤，不把极简或框架默认样式当成唯一答案。

尊重已接受的设计方向与既有语言，但不因“目前如此”就认定它最好。建议说明具体失衡、预期改善、代价与依据，区分已确认缺陷、呈现取舍和待验证的主观疑点。美学不能掩盖正确性、可用性和可访问性问题，不以个人偏好或固定评分代替理由，也不授权改变已接受行为或扩大美化范围。

按待证明的事实选证据：代码足够就直接核对实现；明确要求实际界面验收，或需观察真实呈现、动态与平台行为时，再按 [GUI 验证](../gskd-gui-verification/SKILL.md) 取证。区分推断与实测，只覆盖当前目标。

## 取舍依据与偏好

以当前明确目标、约束与偏好为准，结合适用的已接受设计作取舍。历史选择须连同理由、对象和条件理解；已有实现是线索，存在本身不证明已获认可。新要求替代旧偏好时只更新受影响范围，不把单次认可、否定或分析补充自动固化为跨任务规则。

从已认可的产物及理由中提取可迁移原则，判断它在新对象中解决的问题和适用条件，而非照搬外观或实现。有依据的偏好推断可以支持推荐和授权内的可逆实现，不必逐项等用户确认；区分推断与明确要求，并用实际结果检查是否协调、兑现目标。无相关依据时仍可作专业推荐，但不能把通用最佳实践或模型自身审美冒充用户品味。“轻量”“优雅”“一致”“最小”等方向词须落实到本次优化对象、选择与代价，不默认指最少代码或最小 diff；具体标准复用上述抽象与美学判断，不逐次输出偏好表。自主推进与必要校准按 [orient 的取舍边界](../gskd-orient/SKILL.md#2-判定授权主动推进)处理。

用户的新观察更新事实，明确偏好更新取舍依据；疑问或顾虑则用于检验推荐，不直接当作否决、批准或目标变化。改变推荐时指出是证据、目标或偏好变化，还是原论证有误；既不迎合措辞，也不为保持立场拒绝修正。

## 方案分析与比较

仅调查原因或评估现状时，不为凑比较步骤制造候选。用户要求理想方案或不受现状限制时，分开判断目标结构与迁移路径；现状用于识别真实约束，不把迁移方便当成目标结构最优的理由。探索与实验按用户目的明确要回答的问题、需实现或体验的候选，以及是否需要正式采用建议；实验取证、候选实现与正式接入不是同一交付，不自动扩大或缩小本次承诺。

1. **问题与现状**：说明当前问题、证据和目标，区分代码事实、用户观察与待验证假设。按疑点追查必要的实现、调用方、所有权或生命周期；只读调查可以深入，不因尚未获准修改而停在表面描述，也不因此扩大调查范围。能查到的现状先查，不让用户代查。
2. **实际改变**：说明每个候选改变什么行为、责任或数据流，与保持现状有何不同。已获准实现的候选，不因预计复杂或收益尚未证明就替换为保守方案；发现真实约束冲突时说明依据，不悄悄缩减。文件变短、技术更新、外观相似都不能代替实际改变。
3. **收益与代价**：按任务目标权衡效果、自由度、吞吐、延迟、资源与维护成本，不默认最低成本优先。区分硬约束、已观察缺陷和推测风险，不以无具体依据的未来担忧单独否决方案。性能方案须问“代价搬到哪里”：是否转成内存、缓存失效、同步或释放负担？实验场景与指标应能回答目标问题、区分候选或原因，不只测方便测的路径；没有测量的收益仅作假设，测量细则复用项目验证指南，不另立固定矩阵。
4. **结论与推荐**：区分当前实现的问题、特定负载下的结果、技术方向的适用性与正式采用建议。负面结果先核对实现与实验设计，不据单一候选或指标否定方向，也不为维护方向忽略有效反证。给出推荐与不选其余方案的理由；收益不足可以推荐不采用，但不能替代尚未完成的已授权实验。讨论不构成迁移授权，未获授权就停在建议。
   对约束多个后续部分或撤回成本较高的决定，在已有任务记录或设计说明中简记理由、关键假设、接受的代价和重评条件，不为普通实现细节建立决策日志。切换或压缩记录时保留影响后续选择的依据与适用条件，不把“当前不需要”写成永久禁止。没有相关新证据时沿用；假设被推翻或目标改变时，只重评受影响决定并更新其依赖，不机械执行旧结论，也不重启全部设计。原理由或适用性无法找回时注明未知，先核对影响当前行动的部分，不补造依据；历史采用不自动提供当前实施授权。

## 已授权改造中的设计检查

1. **沿用任务边界**：复用已有目标、授权、不变量、非目标和验收，不因进入设计检查再写一份契约；仅在缺失或新证据使其失效时补齐受影响部分，把本次疑点转成可观察失败条件。对象、授权或在途任务安排有冲突时，按 [orient](../gskd-orient/SKILL.md#接入判断与按需处理) 的对应判断处理，不借评审扩大范围。
2. **落实责任链**：按[链路分析与方案收敛](#链路分析与方案收敛)核对本次受影响实现；控件必须接到真实输入、状态与业务结果，不只是外观或未被调用的接口。
3. **核对接口与执行环境**：说明受影响接口是快照读取、cache-only 查询、阻塞加载还是排队命令，以及谁承担失效、结果提交和收尾。检查真实调用者所在的线程与生命周期，不能因已有入口方便就继承不合适的成本或状态语义：
   - 明确消费者需要的结果及状态 owner，请求携带身份、增量还是快照，排队执行时需重读什么。局部更新由 owner 合并，不用旧快照覆盖无关修改；确需版本快照时明确冲突处理。
   - 区分业务事实、操作进度与操作意图；明确开始、完成、失败、取消有权改变什么、必须保留什么，以及目标或版本变化后结果仍可提交的条件。只建立当前问题需要的状态，不预设固定枚举或 token 数量。
   - render／property getter 不承担冷 I/O 或等待加载；若需冷加载，使用适合的既有后台路径，并核对完成通知与当前身份。
   - 长期 worker 不重复创建可复用的 runtime、连接和缓冲；复用时仍须处理失败、取消及不确定的修改结果，不能自动重放可能已执行的命令。
   - 单项变化不无理由地全量刷新或失效无关消费者；channel／ring 容量有界不代表 drain／refill 单轮工作有界。
   - owner 提供完整状态转换，避免让调用方通过可变 payload 自行拼接失效、加载、接受与恢复定位；只搬方法或加 getter 不证明责任已收回。
   - 涉及超时、取消或部分成功时，检查等待、实际执行、业务提交、结果发布与资源释放中哪些事实会独立变化，以及各事件有权改变什么；停止等待不能直接证明执行已结束。只区分影响当前正确性的事实，不要求各建一个状态、字段或 owner，具体语义以目标接口契约为准。
4. **覆盖调用者**：在本次实现范围内迁移所有受影响调用者，移除被替代的路径、兼容别名和过时说明。候选内部须真实接入；隔离实验保留用于比较的主线基线，不等于正式迁移残留，也不要求因此改动主线。复用或迁移公共机制后，检查调用方叠加的约束是否改变最终行为；入口统一不自动证明契约一致。若某条路径仍有独立契约，说明保留理由，不能用兼容层藏遗漏。
5. **选择充分且克制的修正**：边界应对应所有权、独立变化或不变量。比较方案时关注整体理解成本、重复责任与跨模块补偿，改动量只是迁移成本之一，不替代实现质量。优先复用现有约定，删除已失去用途的层；“最小机制”指不增加无必要的机制，不是为减少 diff 保留不合适的边界。先删除已确认的重复工作，再为有证据的热点选择机制，不预设缓存框架或统一调度器。文件拆分、类型增多或统一入口本身不证明改善，应能指出消除了哪些非法转换或跨模块补偿；纠正测试也必须保留原验收强度，契约变化需用户接受。
6. **交回验证**：沿用任务验收，只补本次疑点及受影响链路的证据，不在每个 Skill 间重写目标或重复有效验证。选择能证明真实接入、失败／取消与对外结果的检查，按授权执行或交给验证负责人。异步问题从共同不变量选择主路径和最有风险的确定性交错，检查事件权限与部分提交，不堆排列、不要求全套矩阵或新测试框架。普通改动不因此展开全项目评审；当前行为证据才支持结论，历史通过、编译或截图不能单独证明整条链正确。

## 成本失衡时回溯需求

方案比较或实施中，新证据表明需求组合与当前约束造成不成比例的实现、运行或维护成本时，不只换实现手段，也重新评估需求取舍；不能仅因难做或代码变长就削减要求。

1. **定位成本来源**：先排除方案选错、重复责任和自行添加的能力或品质要求，不把现成机制的边际不足自动升级为新目标。多项价值看似冲突时，先检查能否通过机制、作用范围或执行时机同时满足，不预设必须牺牲一项，也不无止境搜索所谓两全方案。能保持已接受行为的简化主动执行；确有不可兼顾的证据再提出取舍，不能把 agent 制造的复杂度转成用户必须牺牲的功能。
2. **回到用户目的**：区分必须保持的结果与可协商的手段、适用范围和边际能力，指出哪项要求造成主要成本及依据。为目标承担的成本不自动是缺陷，应说明换来了什么、能否减少及减少后失去什么；数据正确性、安全和关键不变量不能包装成普通简化项。
3. **提出最小取舍**：影响后续方向的重要取舍及时反馈，不攒到交付末尾。推荐保留核心价值的调整，说明减少的成本、失去的能力及剩余风险。例如限制增强引导的适用范围而保留基础操作，而非为覆盖所有极端场景持续堆叠机制。没有测量的收益明确标为推断。
4. **接受后同步基准**：改变已接受的行为、精度、性能目标或范围，须由用户接受；更新任务与验收，标明被替代的要求并重新判断旧证据是否适用。待决定时停止依赖该取舍的新增复杂实现，不阻塞无关的已授权工作。

不因沉没成本硬做到底，也不以“复杂”为由省略必要工作。不擅自缩小范围，不等于不得质疑需求；完整交付是兑现双方最终接受的要求。

## 重复失败时

同类失败反复出现且没有新证据时，停止盲重试：保留具体失败证据，指出哪条假设被推翻，换一个可证伪假设并选择能区分原因的检查。不要通过换断言、缩小验收或吞掉异常使失败消失；也不自动换模型、改配置或按次数强制启动代理。是否需要独立诊断取决于证据和现有授权，不取决于固定计数。

即使每次都有新证据，新反例若持续落在同一状态、责任或提交边界，也在继续添加局部补丁前按[链路分析与方案收敛](#链路分析与方案收敛)回查共同不变量：独立事实是否被同一状态覆盖，多个事件是否越权改写同一事实，调用方是否反复补取消与恢复，旧异步完成是否能改变更新的操作意图。不能默认再加一个条件；没有结构性缺陷证据时不因此重写，必要修正仍服从授权。

## 产出与停止

- **分析与比较**：调查给出问题、证据、结论与未决项；比较方案再说明实际改变、收益／代价与推荐。未获实施授权就停在分析或建议，不据此修改。
- **已授权改造**：问题与证据 → 责任链／修正及取舍 → 当前验证与未覆盖项。证据闭合且无新疑点即停止评审，不无限加审；若真实阻塞使链无法确认，说明缺少的条件、已完成范围和未验证结论，不宣称完成。

遇到领域表达、附加品质、抽象去留、缓存取舍、实验结论、控件接入、代理指标与真实语义、反复交错或超时重试疑问时，按 [设计正反例](references/design-cases.md) 的对应小节补读；定位到具体疑问后不必通读全部案例。
