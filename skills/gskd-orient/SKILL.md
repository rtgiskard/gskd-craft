# 任务定向与续接

## 触发与边界

主要用于已有任务执行期间接到补充、提问、纠正或其他工作项时，判断是更新原任务、插入处理、并行推进、随后处理还是替代原任务，并保持各项授权与续接条件；不以存在歧义为使用前提。任务开始时有多个交付需安排或对象／授权有实质歧义，也可使用。

明确简单的新任务不必先经过本 Skill。执行中的消息沿用这里的判断，不逐项复述或另写固定计划。本 Skill 不取代常驻规则，不提供队列、后台执行或自动恢复能力；专项 Skill 组合是服务当前工作的辅助，不是主流程。

## 接入判断与按需处理

### 1. 绑定对象，再判断消息作用

先读当前请求、直接相关的前文和已有任务记录，确定对象、版本、范围与否定限制；不要仅凭最后一句或熟悉的原因猜测。

编号授权只对应被指向的事项；“别的不动”同时约束相邻优化；“前面发现的问题”回查原发现列表及去向；“整个讨论方案”汇总仍有效的决定、依赖和验收，排除已撤回或替代项。

一条消息可同时有多种作用：
- **提问**：回答其问题，不默认撤销已有任务，也不默认取得修改授权。
- **补充**：将新约束并入当前对象；只有明确替代才删除旧约束。
- **纠正**：先更新对象、现象或约束，撤下不再适用的假设与行动。用户报告的新观察是事实；原因仍待定位，不拿旧原因否定新观察。
- **新任务**：区分独立交付与当前任务的必要步骤，不自动挤掉当前工作。
- **优先级变化**：调整先后顺序；“先做 A”不等于取消 B，也不自动扩大 A 的范围。

### 2. 判定授权，主动推进

分别确定本次获准的是**回答**、**调查**还是**实施**；它们可以组合，但讨论建议不等于批准改动。明确的“执行”“修复”“按这个方案做”结合已绑定范围即构成实施授权，不再反复索要确认。

可从上下文、仓库或可用工具消除的疑问自行解决。已获准完成目标时，依据当前目标、明确偏好和适用的已接受设计，自主选择范围内的实现并推进；多个可行方案或缺少历史偏好记录本身都不构成询问理由。依据的来源、推断与迁移按 [design-review 的“取舍依据与偏好”](../gskd-design-review/SKILL.md#取舍依据与偏好)判断，不因此启动完整评审。

依据不足时，先查相关实现、已接受产物和直接相关讨论，不默认扫描全部历史。用户已委托设计时，先依据任务目标和专业判断形成整体方案，在授权内用可逆实现或必要的小范围样例检验，不等待用户补齐每项品味规格，也不冒称其已认可。影响大量后续工作的关键假设应先取证；只有仍需用户决定、且会实质影响对象、范围、关键偏好、不可逆影响或验收的歧义或冲突才校准具体差异。不得自行覆盖明确要求；不受影响的已授权工作继续，不把询问或样例变成固定流程。

### 3. 分开当前交付与后续事项

确定现在必须完成的结果、保留不动的部分、完成条件，以及之后才讨论或执行的事项。“继续检查、清理完再讨论”先完成已授权的检查与清理，不提前用讨论替代交付；也不借“检查”扩成新的全面整治。

中途出现新事项时，先绑定它针对哪项工作，再分别判断授权与安排：补充／纠正只更新受影响要求；独立事项按依赖、优先级、共享改动和资源冲突选择插入、并行或随后处理；仅记录不等于获准执行，替代原任务须有明确依据。不默认立即切换、取消原任务或把所有事项串行排队；能判断就推进，只有实质歧义才澄清。

有获准且独立的工作项时，按宿主能力评估并行，收益应抵过交接和整合成本，小改动不机械拆分。派发前明确各项范围、共享约束和验收，指定整合责任；有依赖或冲突先安排顺序，不能把互相覆盖的修改当作独立工作。切换或并行期间分别保留目标、授权、真实进度、停点和返回条件，不把插入项完成当作原任务完成；由主代理确认整体交付。

宿主确有任务记录或队列能力时，复用其真实接口和状态语义；没有时只在当前对话简记后续事项及恢复条件，明确这不是已入队或将自动执行。未完成、等待讨论、暂停都不能伪标为 `completed` 或 `abandoned`；记录后续事项不等于授权执行，不承诺后台监听、自动派发或跨会话自动恢复。

### 4. 把实现风险转成验收项

对已授权且涉及状态、异步或资源的改动，先读相关实现与约定，在首次生产修改前于已有任务记录或对话中简记关键不变量与可观察验收，覆盖必要的状态权限、结果有效性和成本边界。已有契约直接复用；简单样式或机械修改只需明确目标、验收与不动项，不新建固定表格或重复计划。

未知原因保留为待查；只有目标或关键约束变化才更新受影响契约，改变已接受要求仍须用户接受。存在实质取舍、责任、生命周期或接入疑点时，按下述组合入口进入针对性设计检查；边界清楚就直接实施，不因有风险契约而自动展开完整评审。具体接口、状态转换和资源检查由设计 Skill 持有。

### 5. 暂停、讨论与恢复

用户要求暂停时，在安全停点停止新的实施操作，保留已做改动，记住当前对象、已完成/未完成部分和停止位置；不擅自回滚。若确有运行中的任务，按宿主能力处理并说明真实状态，不把“要求停止”说成“已经停止”。

讨论期间按问题回答或在授权内调查；只有新的明确授权才改变实施范围。若仅有“做完再讨论”的顺序要求，则先交付当前任务，再进入已约定的讨论，而不是中途暂停。

返回原任务遵守已确定的条件：“先处理 B，再继续 A”已授权连续执行，完成 B 后核实 A 的当前状态，自主从未完成处续接，不再等一次“继续”；明确暂停并等待用户决定的任务则不自动恢复。用户说“继续”时，绑定所指任务，合并插入处理或讨论中已确认的变化；仍未决的方案不混入实施，不重做已完成且证据仍有效的验收。

异常恢复时，先核实中断前进行中操作的实际结果；缺少返回或中断占位结果不等于操作失败或未执行，不据此盲目重复可能已生效的操作。

## 按需组合 Skill

按当前缺口选择方法，不要求先经过本 Skill，也不串成固定流水线：

| Skill | 进入条件与责任 |
| --- | --- |
| [design-review](../gskd-design-review/SKILL.md#触发与边界) | 实质取舍或责任／生命周期／接入疑点，包括实施或收尾中新证据引出的疑点；具体进入判断由该 Skill 持有，只检查受影响边界。 |
| [gui-verification](../gskd-gui-verification/SKILL.md#何时使用) | 明确要求或验收依赖真实界面／输入／平台行为；提供实际证据，不自动重做设计。 |
| [docs](../gskd-docs/SKILL.md#触发与边界) | 文档撰写、实质更新或结构调整；确定读者、用途与深度，组织逻辑并核实内容，不因写作自动重做技术设计。 |
| [delivery-review](../gskd-delivery-review/SKILL.md#触发与边界) | 实现收尾、交付整理或提交；核对既定要求与证据，不重启有效验收。 |
| [recap](../gskd-recap/SKILL.md#触发与参数) | 需要找回历史分析、决定、归属或停点；只读追溯，不从历史获得实施授权。 |

共用已有目标、授权、验收和证据，不另写交接契约。可直接进入专项 Skill；仅需判断标准时补读对应小节，不触发整套流程。技能内容仍在上下文且适用时复用，缺少具体依据时局部补读，不因“再审一次”或“准备提交”重复读取全文；重新应用判断不等于重新读取。出现目标冲突、设计疑点或证据失效才返回相应环节，只更新受影响部分；先前读过技能不免除对新证据的判断。当前上下文足够时，“继续”不自动触发历史回顾。

说明或回顾技能使用时，区分已发现／可用、内容已读取或注入、已应用哪些判断，以及检查证据。读取回执只证明内容已返回，调用次数不证明执行质量；未再次读取也不证明没有复用。结论应对应后续分析、行动和证据，不能只凭技能名或自述；不为可见性强制重读、逐轮播报或维护常驻状态。

## 产出与停止

复杂续接或范围变化时，用简短说明交代：**本次对象与授权、当前交付与不动项、后续事项及恢复条件**；范围清楚的简单请求直接行动，不固定输出一套表格。

当前授权结果满足完成条件才结束执行；只回答的问题答清即可停止。遇到明确暂停、需用户决定的关键歧义或不可达前置条件时，保留实际状态并准确说明停点，不宣称任务完成。当前交付完成不代表后续事项获准实施。

需要对照易误判情境时，按 [历史场景与用法](references/task-scenarios.md) 的对应小节补读：交付与讨论顺序看“Layout：先交付，再讨论”，编号授权与不动项看“72M”，新观察与旧解释冲突看“组件”，整体方案、暂停或优先级切换看“通用续接示例”。不必通读无关案例；案例是历史归纳，不是项目永久规则或本次验证证据。
