= omp 扩展使用参考
:toc:
:toc-title: 目录

扩展随插件加载，命令在 omp 输入框中执行。接入方式见 link:../readme.adoc#setup[README]。
故障续接、工作树位置和显示预设的命令不调用模型，也不向模型上下文添加消息；洞察中的分析与建议使用当前会话模型，会话导出只处理本地数据。

[[recovery]]
== 故障自动续接

`task-recovery` 默认开启，在主会话遇到暂时性上游通信故障后，沿用已有对话和工具结果继续任务，不重放整个任务。
支持连接失败、超时、流异常结束、临时服务错误和限流；账户额度耗尽、认证与配置错误、正常完成或主动取消不触发反复续接。

[source,text]
----
/gskd-recovery status
/gskd-recovery off
/gskd-recovery on
----

`status` 查看开关、等待状态和恢复统计；`off` 取消待恢复任务，`on` 只对后续故障生效。
宿主内置恢复优先；扩展接手后按 30、60、120、300 秒逐步等待，附少量抖动，并遵守可获得的服务端等待提示。
明确的临时故障不设累计次数上限，未确认的通信故障最多试探两次；临时限流沿用宿主分类，不仅凭 quota／billing 等关键词判断。
冷却等待时，输入框上方会显示提示。缺少工具回执、无法确认是否执行时暂停，提示核实结果。

续接回合正常结束且回执齐全才计为恢复成功，同一恢复过程只计一次。统计包含冷却等待的累计耗时及最近完成时间，仅保留在当前会话内存中，不代表业务任务完成。
下一次输入或执行 recovery 命令时，会一次性提醒尚未读过的成功记录。

适用于存活的 TUI、长驻 RPC 和 SDK 主会话，不用于同进程子代理或已退出的一次性 print/json 进程。不重启 omp、不切换模型、不改全局配置，无需额外 checkpoint。
TUI 的 Esc/Ctrl-C、停止、新输入和会话切换会撤销旧恢复；已提交的续接不能撤回。非 TUI 缺少停止信号时，可显式 `off`。

SDK 未暴露“新输入已接纳、仍在图片预处理”的状态，扩展在该窗口内不能保证撤销旧恢复。需要这一保证的 SDK 调用方，应在提交替代任务前显式 `off`，不能只凭宿主空闲状态判断。

[[worktree]]
== 工作树执行位置

`worktree-location` 显示主会话最近一次 bash 执行声明的位置，也识别通过 `write xd://bash` 发起的执行。
在其它工作树执行时，输入区下方靠右显示 `wt: 工作树 · 分支`；回到会话工作树后隐藏，不占底部状态栏。

[source,text]
----
/gskd-worktree status
/gskd-worktree set <path>
/gskd-worktree clear
----

[cols="1,4",options="header"]
|===
|操作 |作用
|默认命令或 `status` |查看完整路径、分支、HEAD、观测来源和显式约定
|`set <path>` |绑定任务工作树，不切换执行目录；尚未观测执行时不显示常驻行
|`clear` |清除显式约定，保留最近执行记录
|===

观测以结构化的 `bash.cwd` 为准，缺省采用会话目录；不追踪 shell 内部 `cd`、`git -C`、远端执行或产物来源。
路径沿用宿主规则，包括 `/` 工作区别名、`@` 前缀和 `file://`；但显式 `set /` 指文件系统根目录。

等待执行回执时标为待确认，最终以规范回执为准。审批拒绝或未执行不算观测，已执行的非零退出和超时仍可记录；目录或 Git 信息不可用时不猜测分支。
实际位置偏离显式约定时仍会提示。成功切换会话／分支后恢复已确认状态，旧回执和查询不会覆盖更新状态；取消切换保留有效的在途观测。
嵌套执行即使外层已取消，仍可能根据最终回执更新位置；无法确认回执归属时提示并忽略，因此部分合法执行也可能不显示。

执行 `/move`、迁移工作区或宿主清除提示后，用 `status` 或下一次 bash 执行刷新显示。
扩展不轮询目录、不切换分支、不拦截执行；非 TUI 通过命令查看。

[[display]]
== 轻量显示预设

`display-preset` 仅用于主 TUI 会话，按需启用，设置不落盘。

[source,text]
----
/gskd-display lite
/gskd-display normal
/gskd-display status
----

[cols="1,4",options="header"]
|===
|预设 |作用
|`lite` |关闭终端图片、工作文字 shimmer 和子代理实时工具预览，收起代理列表；resize 使用 `preserve`，保留历史换行、不回放整段历史
|`normal` |释放预设覆盖，恢复启用前的运行时覆盖状态，不重置为默认设置；期间手动改过的值保留
|===

默认命令与 `status` 查看状态。重复 `lite` 不重拍快照；原本关闭的代理列表保持关闭。
正文和工具输出仍流式显示，不改底部状态栏；工具旋转图标、计时和终端标题动画仍可能刷新。新进程默认不启用预设。

[[insights]]
== Skill 使用洞察

`skill-insights` 将读取事实、显式反馈和模型分析候选分别保存，供 skill 迭代使用。结果不注入主对话，不修改 skill，也不自动执行建议。

=== 查询与反馈

[source,text]
----
/gskd-insights
/gskd-insights --all
/gskd-insights gskd-orient --since 2026-10-01
----

默认查询当前项目；`--all` 扩大到当前 profile 的全部项目，skill 名称和 `--since` 筛选对象与起始日期。
结果包含入口／参考资料读取次数、会话数、重复读取、最近读取、返回文本版本与字节量，以及反馈、候选和确认状态。
版本哈希针对实际返回文本，不代表完整 skill 文件或整个资料目录的版本。

[source,text]
----
/gskd-insights feedback 这里应该先讨论方案
/gskd-insights feedback - --skill gskd-orient 这里应该先讨论方案
/gskd-insights feedback + --skill gskd-orient 本次明确区分了调查与实施授权
/gskd-insights feedback list
----

反馈原文保留，自动绑定项目和会话位置。当前分支附近只有一个 skill／来源组合时预填关联，否则记为 `unknown`；预填不代表用户确认归因。
`--skill` 可明确指定对象，包括尚未读取的 skill。同名但不同来源不会自动合并；反馈倾向默认 `unknown`（未判定），用 `feedback +` 明确正面、`feedback -` 明确问题，不自动推断原文倾向。分类仍未确定，已有历史记录不重写。
`feedback list` 后可加 skill 名称筛选。

模型候选的分类、章节归属和重复问题标签都待判断。用反馈列表中的候选 ID 替换下面的 `<analysis-id>:<index>`，确认或拒绝：

[source,text]
----
/gskd-insights feedback confirm <analysis-id>:<index>
/gskd-insights feedback reject <analysis-id>:<index>
----

同一候选以最新决定为准，重复确认不增加候选数。读取不证明遵守，无反馈不代表成功，不生成综合质量分。

=== 分析与建议

[source,text]
----
/gskd-insights analysis status
/gskd-insights analysis off
/gskd-insights analysis on
/gskd-insights analysis run
/gskd-insights advice
/gskd-insights advice gskd-orient --since 2026-10-01
----

*自动空闲分析默认开启*，开关按 profile 持久保存。主会话空闲 240 秒且没有编辑草稿、排队消息和运行任务时，用当前模型分批分析对话片段，保存证据锚点与成功覆盖范围；各批次之间也需等待空闲。
`analysis status` 显示当前分支待分析片段数、模型、最近状态与存储位置。

`analysis off` 取消等待任务并请求取消在途分析，迟到结果不入库；同 profile 其它实例也遵守该自动分析开关。关闭分析不停止读取事实采集，也不删除已有结果。
`analysis run` 手动处理一个批次，关闭自动分析时仍可使用；自动分析开启时，成功后可继续处理后续批次。
失败或取消不推进覆盖，失败不会立即自动重试，新活动或手动命令可再次触发。

新输入、终端活动、压缩、会话切换和退出会取消旧请求。压缩期间暂停分析；若压缩失败或取消，可能保持暂停，下一轮主任务开始后恢复。
持续讨论时不保证即时覆盖最新内容；没有候选也不能证明任务成功。

`advice` 仅由用户显式触发，用当前模型根据已有统计与反馈生成使用建议。它不额外加载会话正文、不启动反馈分析、不推进覆盖，也不由自动空闲分析生成。
查询范围同样支持 `--all`、skill 名称和 `--since`；按输入上限选择近期完整记录并报告省略数量，建议区分观察与推断并附记录 ID。

=== 采集范围与存储

读取事实只来自成功的 `read` 回执：同一调用去重，主动重复读取分别计数；入口和参考资料归入同一来源，支持 raw 读取及禁用 skill 命令的配置。
识别依赖注册路径或宿主结构化来源，不信任正文伪造标记，无法确认的路径不猜测。命令已注册不等于模型可见。
bash／eval 内部读取、自动注入及未转发到扩展的子代理事件不保证覆盖，不回填安装前历史。

数据位于当前 profile 的 agent 数据目录下 `gskd-skill-insights.sqlite`，支持持久化和并发写入。事实、分析与人工决定分别保留，不另存完整会话副本。
原会话删除后，证据锚点不保证可回查；需要保留完整对话时，使用下述会话导出。

[[export]]
== 本地会话导出

`session-export` 将会话和洞察统计保存为独立的本地 `.tar.zst` 快照，不调用模型、不发送网络请求、不维护增量进度。
需要系统 PATH 中有 `tar` 和 `zstd`。

[source,text]
----
/gskd-export
/gskd-export --all
/gskd-export --source "/path/to/agent" --out "/path/to/exports"
/gskd-export --stats-only
----

[cols="1,4",options="header"]
|===
|范围 |内容
|默认 |当前项目的会话文件、关联子会话、附件和洞察统计，附文件哈希清单
|`--all` |当前 profile 的全部项目，同时扩大统计范围，并包含当前会话自定义的 session 目录
|`--source AGENT_DIR` |从指定 agent 数据根目录读取 `sessions/` 和洞察数据库，不额外采集当前会话目录
|`--stats-only` |只导出统计快照和清单，不含完整对话，也不要求会话目录存在
|===

导出前先保存当前会话已有的完整记录，不等待或停止生成，未完成消息不在本次快照中。保存失败则中止导出。
即使指定 `--source` 或 `--stats-only`，仍先保存当前会话，但不改变所选导出范围，也不触发或等待旁路分析。

`statistics.json` 包含所选范围内的洞察事件、原始反馈、候选、人工决定与分析覆盖，并参与哈希清单。
缺少洞察数据库视为无统计记录；若有会话文件，仍附带空统计快照。最新讨论可能尚未进入统计，需要保留对话供后续分析时使用默认导出。

统计读取异常时跳过 `statistics.json`，继续导出会话，并在命令结果和包内清单记录告警；会话读取、文件写入或打包失败仍会中止导出。
没有会话文件但有统计记录时可仅导出统计；二者皆空时只提示，不生成压缩包。统计读取失败且没有会话文件时同样不打包，包括 `--stats-only`。

=== 来源边界

导出沿关联子会话与历史会话引用继续收集所选存储目录内的内容，支持已迁移父会话的关联和嵌套来源，并避免重复打包。
不跟随符号链接，不读取存储目录外的引用，也不按聊天正文里的路径采集文件；不打包整个配置目录或项目源码。
会话日志 JSONL 仅截取完整事件，未完成部分留到下次；普通附件即使后缀为 `.jsonl`，仍按原始字节保留。

=== 保存位置

`--out DIRECTORY` 指定本次输出目录，优先于环境变量；路径含空格时加引号。
默认保存到当前 profile 的 agent 数据目录下 `exports/`，普通默认 profile 通常为 `~/.omp/agent/exports/`。
也可在当前 profile 的用户 `.env` 中设置，重启 omp 后生效：

[source,dotenv]
----
GSKD_EXPORT_DIR=~/.omp/exports
----

文件名为 `omp-export_<本地时间YYYYMMDD-HHmmss>_<8位随机十六进制ID>.tar.zst`，不带时区；清单中的 `createdAt` 使用同一时刻的 UTC 时间。
命令完成后显示保存位置及统计告警。这是会话与统计快照，不是源码备份或完整开发环境迁移包。
