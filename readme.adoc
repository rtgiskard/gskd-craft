= gskd craft

工程协作技能与 oh-my-pi（`omp`）配套扩展。技能提供工作方法，扩展提供宿主内的运行辅助；两者按需使用，不组成固定流水线。

[[setup]]
== 接入与更新

=== omp

将仓库克隆到独立源码目录，在仓库根执行：

[source,shell]
----
omp plugin link .
----

链接直接指向源码，无需复制文件，不搬迁现有配置或会话数据。使用命名 profile 时改为 `omp --profile work plugin link .`。
首次接入或更新仓库后，启动新会话，omp 会发现技能并加载扩展。

=== 其它宿主

按宿主约定接入 `skills/` 下的技能目录，保留 `SKILL.md`、`references/` 和相对引用。`extensions/` 仅用于 omp。

能力取决于宿主工具、权限和环境。已读且仍适用的内容可以复用；发现、读取或注入技能不等于落实要求，应以实际行动和证据判断。

== 待议方向

以下仅为探索方向，尚未实现或安排实施：

* `gskd-inspect`：考虑合并故障定位与性能调查，以可证伪假设、真实负载和可区分原因的实验建立证据；设计取舍仍由设计技能承担，调查不构成修复或优化授权。
* 模型独立判断与客观性：针对用户观察到的 `6.1-sol` 缺少主见、顺着用户说、不够客观的问题，探索性格设定及用户／模型切换机制，但不预设它就是解法。原因与适用范围待验证；目标是依据证据形成判断、指出前提问题并合理修正，而非刻意反对。
