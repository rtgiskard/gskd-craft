= gskd craft

工程协作 skill 与工具配套能力集合，覆盖任务续接、设计取舍、界面验证、交付复查和脉络回顾。
skill 不限于 omp，可按目标宿主的约定接入。

== skills

* `gskd-orient`：处理任务执行中的补充、纠正、工作项插入、并行安排与暂停续接
* `gskd-design-review`：检查设计取舍、责任边界、生命周期与实际接入
* `gskd-gui-verification`：验证真实界面、输入交互及平台行为
* `gskd-delivery-review`：对照已接受要求，核对实现、证据和交付边界
* `gskd-recap`：梳理分析、决定、进展和续接位置，不自动执行历史任务

各 skill 按需使用，不组成固定流水线；具体执行能力由宿主工具、权限和环境决定。

== omp 扩展

`task-recovery` 为仍在运行的 omp 主会话自动续接暂时性上游通信故障，覆盖连接失败、超时、流异常结束、临时服务错误和限流，不限于 HTTP/2。
优先使用 omp 内置恢复；仍未恢复时，按 30、60、120、300 秒逐步等待，附加少量抖动，并遵守错误中可获得的服务端等待提示。明确的临时故障不设累计恢复次数上限；未确认的通信故障最多试探两次。

扩展随包自动加载，主会话默认开启。可在会话内使用：

[source,text]
----
/gskd-recovery status
/gskd-recovery off
/gskd-recovery on
----

`status` 只显示状态，不写入模型上下文或触发模型请求。正常运行时不显示 recovery；仅在冷却等待期间，在输入框上方显示警示色标签与弱化色的重试次数、等待时间和取消提示，不占底部状态栏。提示按事件更新，不逐秒重绘；续接开始、取消或关闭后移除。`off` 取消待恢复任务，`on` 对后续故障启用恢复，不追溯唤醒已停止的任务。

自动续接后的模型回合正常结束且工具回执齐全时，才记为一次成功恢复；同一恢复过程中的多次重试不重复计数，提交、失败、取消或被用户替代不算成功。这只证明通信恢复并正常结束，不判断用户任务的业务结果是否正确。统计记录成功次数、从首次故障到正常结束的累计耗时（含冷却等待）和最近完成时间。用户下一次输入或执行 recovery 命令时，一次性提示尚未提醒的成功记录；`status` 同时显示累计统计，不增加模型请求或上下文消息。统计仅保存在当前会话内存中，进程退出或切换会话后重置。

恢复沿用原会话和工具结果，不重放整个任务。正常完成、主动取消、认证与配置错误等不会自动拉起。真正缺少工具回执、无法判断是否执行的操作会暂停并提示核实，不伪造结果。

该扩展不重启 omp、不切换模型、不修改全局配置，也不要求额外 checkpoint。支持存活的 TUI、长驻 RPC 或 SDK 主会话；不对同进程子代理启用恢复，一次性 print/json 进程退出后也不会继续。
TUI 的 Esc/Ctrl-C、会话停止信号、新输入及会话切换会撤销旧恢复。公开接口无法撤回已提交的续接；对没有会话停止信号的非 TUI 空闲取消，也无法保证全部观测到。此时可显式使用 `off`。


== 目录

`skills/` 下每个目录对应一个 skill，以 `SKILL.md` 为入口，补充资料放在各自的 `references/` 下。
`extensions/` 为 omp 配套扩展。安装或迁移时保留完整目录，避免破坏相对引用。

== 接入

=== 通用方式

按目标宿主的安装或发现约定接入 `skills/` 下的 skill 目录。

=== omp

将仓库克隆到独立源码目录，在仓库根执行一次：

[source,shell]
----
omp plugin link .
----

omp 将仓库登记为 `gskd-craft` 包，之后启动新会话即可自动发现 skill 并加载扩展，无需反复指定路径或复制文件。
链接直接指向源码，不需要安装额外依赖，也不会搬迁现有配置、凭证或会话数据。

使用命名 profile 时，在相应 profile 下登记：

[source,shell]
----
omp --profile work plugin link .
----

== 更新

更新仓库后重新加载；omp 用户启动新会话即可。
